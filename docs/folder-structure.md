# 폴더 구조 — 경로 틀을 데이터 유형과 온톨로지에 쓰기

## 결론

1. **사내 문서 폴더의 뜻은 계층보다 이름 안의 식별자에 있다.** 폴더 하나가 계약 하나, 협력사 하나인 저장소가 대부분이다(아래 실측).
2. **폴더·파일 이름을 하나의 경로 틀로 본다.** 칸마다 역할(식별자·연도·옛 판·원자료·종류)을 정한다.
   - 예: `{계약번호}_{차수}/{계약번호}_{문서 제목}`, `{협력사코드}_{협력사명}/{YY}년 신용평가.pdf`
3. **판정은 규칙으로 하고, 칸과 개념의 대응은 관리자가 확정한다.** 「이 식별자는 계약」 같은 대응이다. LLM은 대응을 제안만 한다.
4. **경로에서 얻은 사실은 내용에서 뽑은 사실보다 약하게 다룬다.** 둘이 어긋나면 내용을 따르고, 어긋난 것을 알린다.
5. **경로는 바뀐다.** 변경계약 때 차수 폴더 이름이 바뀐다. 그래서 경로에서 얻은 사실은 늘 경로에서 다시 계산한다.

## 실측 (운영 서버, 2026-11, `storage__list_files`)

| 모양 | 저장소 | 실측 |
|---|---|---|
| 건 폴더 | contracts | 폴더 1,079개 중 1,078개가 `KR-CT{YYMM}{순번5}_{차수}`. 파일 7,707건 모두 폴더 번호로 시작. 폴더당 중간 7건(품의서·메일·견적·계약서). 차수 0: 873, 1: 139, 2: 44, 3: 13… 같은 번호의 차수 폴더가 둘 이상인 계약 11건 |
| 대상 폴더 | credit | 241개 모두 `KR{6자리}_{회사명}`. 파일 이름 63%가 「YY년 신용평가」 |
| 파일 이름 식별자 | intro | 폴더 없음. 파일 이름의 `KR{6자리}` 147개 중 120개가 credit의 코드와 같음 |
| 종류/기간 | work-square | `WPR(팀)/2024년/…`, `KPI/2024/경쟁평가율/Raw/…`, `…/History/…` |
| 시스템 폴더 | dream-rsi, reference, gps | 앱이나 데이터 수집이 만든 폴더(`documents/doc-20261028-xxxx`, `uploads/quotes`) |
| 평평함 | intro, scoring, external, costdb | 폴더 없음 |

맨 위 분류는 저장소 자체다(`D:\gp\1.계약품의정보`, `2.신용평가서`…).

## 칸의 역할 (`services/pathshape`)

| 역할 | 판정 | 예 |
|---|---|---|
| 식별자 | 형제 폴더 중 앞머리 모양(숫자를 자릿수로 바꾼 틀)이 같은 것이 5개 이상이고, 영문자와 숫자 4자리 이상이 섞인 것. 한 부모 아래 여러 갈래(계약 폴더와 협력사 폴더)가 섞여 있으면 갈래마다 따로. 뒤따르는 부분은 번호(차수)나 이름 | `KR-CT{9자리}` + 번호, `KR{6자리}` + 이름 |
| 파일 이름 식별자·연도 | 같은 묶음의 파일 이름에 60% 이상 나오는 토큰. 식별자·연도 폴더는 형제를 한 묶음으로 본다 | `KR{6자리}`(intro), `{2자리}년`(credit) |
| 연도 | 이름 전체가 연도·연월인 폴더 | `2024`, `2024년`, `2026-10` |
| 옛 판 | History, old, 구버전, 백업, archive | `KPI/2024/MBR Master File/History` |
| 원자료 | Raw, 원본, 원자료 | `KPI/2025/경쟁평가율/Raw` |
| 종류 | 식별자도 연도도 아닌 형제 폴더. 맨 위는 2개부터 | `WPR(팀) · KPI · MBR(팀)` |

식별자에서 빼는 것:
- 숫자만인 토큰(날짜일 수 있다)
- 한글과 숫자로만 된 토큰(「3080억원기준」 같은 금액)

저장소 모양은 다음 순서로 정한다.
1. 폴더가 없으면 평평함
2. 맨 위 식별자 폴더가 문서의 절반 이상을 덮으면 건 폴더(뒤가 이름이면 대상 폴더)
3. 연도 폴더 아래 문서가 절반 이상이면 종류/기간
4. 그 밖은 계층

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| P0 | 옮긴 문서의 내용 분석이 비는 버그 수정, 관측한 날(`doc_date`)이 「YY년」·「YYYY년」·연도 폴더를 읽음 | 완료 |
| P1 | 경로 틀 판정, 운영 도구 `ops__folder_profile`, 정보 현황의 「저장소의 경로 틀」 표 | 완료 |
| P2 | 경로 틀 확정 → 규칙 추출(출처 표시 `path`), LLM 추출에 「이 문서가 속한 개체」, 폴더와 내용 불일치 알림 | 완료(아래). 차수를 상태로 기록하는 것과 형식 그래프의 폴더 표는 남음 |
| P3 | 협력사 코드로 저장소 사이 개체 묶기(credit·intro·contracts) | |
| P4 | 출처 목록과 저장소를 식별자로 대조(확보한 계약 / 신규 계약), 「출처 미확인」을 식별자로 판정 | 계약조회 수집 스킬이 0건이라 먼저 고쳐야 함 |

## P2 — 경로 틀 확정 (내용 분석 ②″)

1. 후보는 경로 틀의 식별자 칸이다(파일 이름이 폴더의 식별자를 되풀이하는 칸은 뺀다).
2. 칸마다 **값이 내용 그래프의 어느 개념 개체와 겹치는지** 센다. 가장 많이 겹친 개념이 제안이다(LLM 없음).
   - 대상 폴더(`KR{6자리}_{회사명}`)는 뒤의 이름(회사명)도 견준다. 기본은 회사명을 개체 이름으로 쓴다.
3. 관리자가 칸마다 개념을 고르면 확정이다. 칸은 지금 판정한 후보에서만 고를 수 있고, 개념은 확정한 스키마에 있는 것만 된다.
4. 확정하면 바로, 그리고 분석이 끝날 때마다 **경로에서 개체를 전부 다시 만든다**.
   - 출처 표시는 `path`, 근거는 「폴더 KR-CT240100002_1」, 관측한 날은 `doc_date`
   - 문서마다 결과를 갈아 끼우거나(_write) 옮길 때(_copy)는 `path` 사실을 건드리지 않는다. 폴더 이름이 바뀌어도(차수) 경로에서 다시 만든다.
   - 스키마 판이 바뀌면 옛 대응은 쓰지 않는다(다시 확정).
5. LLM 추출에는 「경로가 말하는 것: 계약 KR-CT…」 한 줄을 문서 앞에 함께 준다. 지문(fp)에는 넣지 않는다. 그래서 이미 분석한 문서를 다시 부르지 않고, 새로 바뀐 문서부터 받는다.
6. **폴더와 내용 불일치**: 경로는 계약 A인데 내용에서 뽑은 같은 개념·같은 모양의 이름이 A가 아니면 알린다. 내용을 따른다.

## 하지 않는 것

- 칸과 개념의 대응을 자동으로 확정하지 않는다.
- 폴더를 옮기거나 이름을 바꾸지 않는다(판정만 한다).
- 시스템 폴더를 사람의 분류로 해석하지 않는다. 시스템 폴더 안의 식별자는 문서 ID로만 본다.
