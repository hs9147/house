# 온톨로지 층위 — 지식과 정보의 구분

## 결론

1. **"고정부 = 지식, 변경부 = 정보"를 그대로 쓰지 않는다.** 변하는지 여부만으로는 지식과 정보를 가를 수 없다.
   - 고정이어도 지식이 아닌 것이 있다(결재란·면책 문구 같은 형식).
   - 고정이어도 정보인 것이 있다(사업자번호 같은 대상의 신원 속성).
   - 지식도 바뀐다(규정 개정).
2. **두 기준으로 가른다 — ① 뜻의 역할, ② 변화 속도.** 그 결과 내용 그래프의 개념은 아래 네 층위 중 하나다.
3. **층위는 관리자가 확정한다.** LLM은 제안만 하고, 데이터 수집의 열별 변화율은 판정 근거로만 쓴다(자동 확정하지 않는다).
4. **시점에 매인 사실(상태·사건)은 지우지 않고 쌓는다.** 문서마다 하나의 관측으로 남고, 가장 늦게 본 값이 지금 값이다.
5. **기준 지식은 판으로 관리한다.** 시행일이 가장 늦은 문서가 지금 판이고, 옛 판은 지우지 않고 "대체됨"으로 표시한다.

## 층위의 정의

| 층위 | 뜻 | 예 | 바뀌는 방식 | 시스템이 하는 일 |
|---|---|---|---|---|
| 구조 | 개념·관계의 종류 자체 | 스키마, 양식의 열, 템플릿 뼈대 | 관리자가 판을 바꿀 때만 | 확정 판 번호 |
| `reference` 기준 지식 | 일의 기준이 되는 내용 | 용어 정의, 규정 조문, 절차, 코드, 기준값 | 개정(시행일) | 개정 계열을 묶고 지금 판 표시, 항목은 전부 검토 |
| `entity` 대상 | 신원이 있는 것 | 협력사, 품목, 부서, 사람 | 거의 안 바뀜 | 같은 대상 묶기 |
| `state` 상태 | 시점마다 값이 바뀌는 것 | 신용등급, 계약 상태, 재무위험 | 수시로 | 관측한 날과 함께 누적, 최신 값 표시 |
| `event` 사건 | 일어난 때가 있는 것 | 계약, 견적, 발주, 평가 | 발생 | 관측한 날·효력 기간 기록 |

- **지식** = 구조 + 기준 지식(+ 대상의 신원).
- **정보** = 상태 + 사건.
- 상태·사건에 닿는 관계는 **시점에 매인 관계**(`temporal`)다. 관리자가 따로 정하지 않으면 이렇게 판정한다.

## 판정 규칙

| 무엇을 | 어떻게 | 확정 |
|---|---|---|
| 개념의 층위 | 스키마 제안(LLM)이 정한다. 적지 않으면 `entity` | 관리자(① 스키마 확정) |
| 관계의 시점 매임 | 끝의 개념이 상태·사건이면 시점에 매인다. 스키마에 직접 적은 값이 먼저 | 관리자 |
| 수집 목록 열의 고정·변경 | 이미 받은 건을 다시 받을 때마다 그 열의 값이 바뀌었는지 센다. 이렇게 비교한 횟수가 20번 이상인 열만 판정한다. 바뀐 비율이 2% 이하면 고정, 10% 이상이면 변경, 그 사이는 모름 | 판정만 보여 준다(층위를 바꾸지 않는다) |
| 관측한 날 | 파일 이름의 날짜 → 없으면 파일 수정일. 데이터 수집 목록은 행마다 「수집 바뀜」 | 자동 |
| 효력 기간 | 문서에 적힌 기간만 남기고 지어내지 않는다. 시작이 끝보다 늦으면 기간만 버린다 | 자동 |
| 지금 값 | 시점에 매인 관계에서 같은 관계·방향 중 가장 늦게 본 값 | 자동 |
| 지금 판 | 파일 이름에서 날짜·판 표시(v1.2, 개정3 등)를 뗀 이름이 같은 문서를 한 계열로 묶는다. 그중 부칙 시행일이 가장 늦은 것이 지금 판이다. 시행일이 있는 문서가 없는 문서보다 앞서고, 시행일이 같거나 모두 없으면 가장 늦게 수정된 것 | 자동 |
| 정의 충돌 | 지금 판의 문서끼리 같은 용어를 다르게 정의한 경우만. 옛 판과 다른 것은 개정으로 보고 충돌에 넣지 않는다 | 표준 용어 후보로 알림 |

## 에이전트가 답하는 규칙

- 기준 지식은 **근거 문서(지금 판)**로 답한다. 근거가 옛 판이면 `superseded`로 표시된다.
- 상태·사건은 **언제 기준인지(관측한 날)**를 함께 쓴다.
  - 지금 값이 필요하면 수집 스킬(`skills__run`)로 바로 조회한다.
  - 특정 날 기준이면 `as_of`로 그날 참이던 것만 본다.

## 재구성 절차

층위와 시점이 없던 때 만든 내용 그래프는 다음 순서로 다시 만든다(온톨로지 관리 → 내용 분석 → ⑥ 재구성).

1. 지울 범위를 고른다.
   - **추출 결과만:** 확정한 스키마·양식·템플릿·묶기 기준·사람 정답은 남긴다.
   - **확정한 것까지 모두:** 전부 지운다.
2. 형식 그래프의 판 정보(시행일·개정 계열)를 다시 만든다. 1번 뒤에 자동으로 이어서 돈다.
3. ① 스키마에 층위를 넣어 확정한다. 추출 결과만 지웠더라도 기존 스키마에 층위가 없으면 다시 확정한다.
4. ② 데이터 수집 목록의 열 대응을 확정한다(시점 열은 「수집 바뀜」).
5. ③ 분석을 시작한다.

원본 문서와 문서 색인은 재구성으로 지워지지 않는다.

## 하지 않는 것

- 층위를 자동으로 확정하지 않는다(변화율은 근거로만 보여 준다).
- 옛 판의 문서와 옛 관측은 지우지 않는다(그때의 기준으로 답할 근거다).
- 이력에서 경향을 계산하는 파생 지식, 상태 값의 이상치 알림은 아직 없다.
